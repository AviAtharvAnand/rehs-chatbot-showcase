To access NRP LLMs through the [Envoy AI Gateway](https://aigateway.envoyproxy.io), you need to be a [member of a group with the LLM flag](/documentation/userdocs/start/hierarchy). Your membership info is on the [namespaces page](/namespaces).

Start by [creating a token](/llmtoken). The token authenticates against an OpenAI-compatible endpoint:

<Card title="Envoy AI API endpoint">
`https://ellm.nrp-nautilus.io/v1`
</Card>

You can use this endpoint with `curl` or any OpenAI-compatible client.

```bash
curl -H "Authorization: Bearer <your_token>" https://ellm.nrp-nautilus.io/v1/models
```

<Aside type="caution" title="About Max Output Tokens">
Only specify `max_tokens` / `max_output_tokens` / "Max Output Tokens" when you understand what they mean. This is the **maximum output length** under the context length, not the total context length. If your client requires a value, set it to roughly 1/3–1/4 of the context window. **Never specify the full context length here — the model will error.**
</Aside>

## Python

```python title="nrp-llm.py"
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url="https://ellm.nrp-nautilus.io/v1",
)

completion = client.chat.completions.create(
    model="gpt-oss",
    messages=[
        {"role": "system", "content": "Talk like a pirate."},
        {"role": "user", "content": "How do I check if a Python object is an instance of a class?"},
    ],
)

print(completion.choices[0].message.content)
```

## Bash + curl

List available models:

```bash
curl -H "Authorization: Bearer <TOKEN>" https://ellm.nrp-nautilus.io/v1/models
```

Send a chat completion:

```bash
curl -H "Authorization: Bearer <TOKEN>" -X POST "https://ellm.nrp-nautilus.io/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-oss",
    "messages": [
      {"role": "user", "content": "How do I check if a Python object is an instance of a class?"}
    ]
  }'
```

For pre-built configurations for coding CLIs (OpenCode, Crush, Kimi CLI, Claude Code, Copilot CLI, pi), see [Client Configurations](/documentation/userdocs/ai/llm-managed/client-configs).

## Isolating Cached Responses

<Aside type="caution">
API users sharing a tenant should set the configuration below if their prompts and responses should be cached only for themselves and not for others. The trade-off is slightly lower performance because your cache won't be shared.
</Aside>

In your API call, specify a `cache_salt` key inside `extra_body`. The value must be a base64-encoded random string of at least 256 bits (43+ characters before encoding) that is known only to you.

```python
response = client.chat.completions.create(
    model=model,
    messages=messages,
    extra_body={
        "cache_salt": "YWJjZGVmZ2hpamtsbW5vcHFyc3R1dnd4eXphYmNkZWZnaGlqa2xtbm9wcQ==",
        "chat_template_kwargs": {
          "enable_thinking": True,
          "thinking": True,
          "preserve_thinking": True,
          "clear_thinking": False
        }
    }
)
```

This is supported on vLLM and SGLang models. Without a cache salt, your cached prompts and responses can mix with other users' caches — which is convenient for shared utility queries but **prevents privacy** for sensitive prompts and may cause irrelevant cached results to surface in your output.

We would like to apply this automatically per API key but several upstream issues are blocking it: [Envoy AI Gateway #1985](https://github.com/envoyproxy/ai-gateway/issues/1985), [Open WebUI #23012](https://github.com/open-webui/open-webui/issues/23012).
